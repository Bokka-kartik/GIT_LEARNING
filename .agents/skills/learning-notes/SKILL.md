# Learning notes

Write for the future version of the reader who has forgotten the context and wants the useful idea quickly.

## Writing shape

- Use a few genuine questions as anchors, not a question heading for every section.
- Answer the anchor directly, then explain the idea in short, connected prose.
- Include why it matters, one concrete example, and the main trade-off when useful.
- Use descriptive headings for supporting ideas. Use bullets for short comparisons or steps, not as the whole explanation.
- Be concise without making the note so bare that it stops teaching.
- Compare tools by the user's needs; avoid declaring a universal winner.
- Link to deeper references instead of retelling them.

## Accuracy and editing

- Ground claims in a source or observed evidence. Separate what is known from what still needs checking.
- Treat installed tools, project descriptions, model availability, prices, and free quotas as time-sensitive. Date snapshots when useful.
- Do not infer that a tool is configured or running just because it is installed or a folder exists.
- Remove generic introductions, repeated caveats, filler learning plans, marketing claims, and sections that add no useful understanding.
- Keep secrets, credentials, and personal data out of notes.
- When revising, preserve useful facts and shape them around a few meaningful questions. Do not add a section just to fill a template.
